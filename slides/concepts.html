You could just call an API

The honest counter-argument

A local small model will be

  • slower
  • dumber
  • confidently wrong

So self-hosting is

a trade, not an upgrade.

Knowing when the trade is worth it is the actual skill. That is what today is for.

Everything after this slide is about making the trade deliberately, instead of by accident.

Layer 1 · a model is a file of numbers

safetensors

The native format. Full precision, large. Needs PyTorch or vLLM to run.

GGUF ← what you will use

One self-contained file for llama.cpp: weights plus the tokenizer plus the chat template. Usually quantised.

Where they come from

Hugging Face is the de facto registry — think npm or Docker Hub, for models. Repos are owner/name; quantised re-uploads end in -GGUF.

Trust order for a GGUF: the author's own repo → ggml-org (the llama.cpp team) → unsloth / bartowski.
© MHP Management- und IT-Beratung GmbH

Layer 1 · quantisation: compressing the numbers

A model trained at 16 bits per weight can run at 4 bits with modest quality loss — 4× smaller, and on a CPU often faster, because you move less data.

SuffixBitsQualityUse it when
Q8_08Near-losslessYou have RAM to spare
Q6_K6ExcellentGood default on 16 GB
Q5_K_M5Very goodBalancing act
Q4_K_M4Good← the workshop default
Q3_K_M3Noticeably worseDesperate for RAM
Q2_K, IQ2_*2PoorDemos of what quantisation destroys

Rule of thumb: RAM for weights ≈ file size + 10–20%

Layer 1 · reading a repo id — and the case trap

ggml-org / Qwen3-4B-GGUF  /  Qwen3-4B-Q4_K_M.gguf
   │           │                    │

Filenames are case-sensitive and conventions differ per owner. ggml-org uses Qwen3-1.7B-Q4_K_M.gguf; Qwen uses lowercase qwen2.5-coder-1.5b-instruct-q4_k_m.gguf. A retyped name is a 404 — copy exactly.

Layer 3 · one slot, several models

Loading a model costs gigabytes and seconds. Four llama-server processes fighting over 16 GB will not work.

:8090 ──┬──> llama-server (chat) ← loaded now ├──> llama-server (coder) ← starts on demand ├──> llama-server (embed) ← starts on demand └──> llama-server (tiny) ← starts on demand

llama-swap presents one API and starts/stops engines behind it. Idle models die after a TTL and your RAM comes back. That is what makes specialists practical on a laptop.

© MHP Management- und IT-Beratung GmbH

llama-swap · the config, whole

healthCheckTimeout: 300     # seconds to wait for an engine to become healthy
startPort: 18080            # first port handed out to engines
globalTTL: 0                # 0 = never auto-unload; per-model ttl wins

macros:                     # text substitution. unknown macro = HARD error
  model-dir: "/home/YOURNAME/models"
  llama-server-path: "llama-server"
  common-args: "--host 127.0.0.1 --port ${PORT} --jinja"

models:
  chat:                     # the id clients put in "model"
    cmd: >
      ${llama-server-path}
      -m ${model-dir}/Qwen3-1.7B-Q4_K_M.gguf
      ${common-args} -ngl 0 -c 8192 -np 1
    ttl: 600                # unload after 10 min idle → RAM returns
  embed:
    cmd: >
      ${llama-server-path}
      -m ${model-dir}/nomic-embed-text-v1.5.Q8_0.gguf
      ${common-args} -ngl 0 -c 2048 --embedding
    ttl: 600

Full file in the repo: configs/llama-swap/config.yaml

© MHP Management- und IT-Beratung GmbH

llama-swap · what each part does

KeyWhy it matters
modelsThe only required top-level key. Each entry's key is the public model id.
cmdThe only required per-model key — the command that starts the engine.
${PORT}Auto-assigned free port. Reserved, like ${MODEL_ID} and ${PID}.
proxyDefaults to http://localhost:${PORT}. Omit it when cmd uses ${PORT}. A mismatch here is the #1 llama-swap failure.
macrosYour own substitutions. ${HOME} is not a macro — env vars are not expanded, and an unknown name fails loudly at startup.
ttlIdle seconds before unload. 0 = keep resident. This is the RAM reclamation.
healthCheckTimeoutDefault 120 s, minimum 15. Too short for a cold load that must download weights.
aliasesExtra names — e.g. impersonate gpt-4o-mini so existing tooling works unchanged.
Validate before running: llama-swap --config config.yaml --validate (v252+). Edit live with --watch-config.
© MHP Management- und IT-Beratung GmbH

llama-swap · a production route, annotated

local-fast:
  cmd: >
    llama-server
    -m /models/…/Qwen3.8-9B-Q6_K.gguf
    --host 127.0.0.1
    --port ${PORT}
    -c 131072
    --parallel 4
    --cache-type-k q8_0
    --cache-type-v q8_0
    --flash-attn on
    --jinja
    --reasoning-budget 0
    -ngl 999
  ttl: 3600
  proxy: http://127.0.0.1:${PORT}
  • --host 127.0.0.1 — never bind the LAN by accident
  • --cache-type-k/v q8_0 — halves the KV cache; the standard RAM lever
  • --reasoning-budget 0 — stops a thinking model burning the whole output budget on thought
  • --jinja — the model's own chat template; required for tool calling
  • -ngl 999 — offload everything to GPU. On your laptop: -ngl 0.
  • -c 131072 --parallel 4 — a 128 GB box's numbers. Yours: -c 8192 -np 1.
Same structure, different scale. Take the shape, not the numbers.
© MHP Management- und IT-Beratung GmbH

Layer 4 · several backends, one endpoint

Your local llama-swap, a colleague's GPU box, OpenRouter, Google's free tier — different URLs, different keys.

LiteLLM puts one endpoint in front of all of it

  • Routing — fast-model local, big-model cloud
  • Fallback — local died? retry on the cloud. This is what makes a workshop survivable.
  • Uniform API — 100+ providers behind OpenAI-shaped endpoints

Clients talk to :4000 and never learn where the tokens came from.

© MHP Management- und IT-Beratung GmbH

LiteLLM · the config, whole

model_list:
  - model_name: local-chat          # PUBLIC alias — what clients ask for
    litellm_params:
      model: openai/chat            # openai/ = protocol · chat = upstream id
      api_base: os.environ/LOCAL_API_BASE   # http://host.docker.internal:8090/v1
      api_key: os.environ/LOCAL_API_KEY     # "dummy" for a keyless local server
      timeout: 600                  # survive a cold llama-swap load

  - model_name: resilient           # same backend, cloud behind it
    litellm_params:
      model: openai/chat
      api_base: os.environ/LOCAL_API_BASE
      api_key: os.environ/LOCAL_API_KEY
      timeout: 600

router_settings:
  fallbacks:
    - resilient: ["cloud-fast"]     # local down? retry on the cloud

general_settings:
  master_key: os.environ/LITELLM_MASTER_KEY   # must start with sk-

Full file in the repo: configs/litellm/config.yaml

© MHP Management- und IT-Beratung GmbH

LiteLLM · what each part does

KeyWhy it matters
model_nameThe alias the client sends. A routing group, not a model.
litellm_params.modelWhat LiteLLM asks upstream. openai/ is a protocol selector; the part after it must match the server's id byte-for-byte.
api_basehost.docker.internal, never 127.0.0.1 — inside the container, loopback means the container.
api_keydummy is correct for a keyless local server. Real keys go through os.environ/NAME.
timeoutPer-route. Order it above the global timeout, above llama-swap's health check — or retries re-trigger cold loads.
fallbacksThe resilience demo: kill the local server, the request still answers.
master_keyOnce set, every key-bearing endpoint 401s without the bearer — including /v1/models. /health/liveliness stays open.
drop_params: true is load-bearing for llama.cpp: it strips a null encoding_format that would otherwise 400 every embedding request.
© MHP Management- und IT-Beratung GmbH

LiteLLM · docker-compose.yml, and the one line that matters

services:
  litellm:
    image: ghcr.io/berriai/litellm:v1.106.4
    command: ["--config", "/app/config.yaml",
              "--port", "4000"]
    ports: ["4000:4000"]
    volumes:
      - ./config.yaml:/app/config.yaml:ro
    env_file: [.env]        # gitignored
    extra_hosts:            # ← THE line
      - "host.docker.internal:host-gateway"
    restart: unless-stopped

Why extra_hosts

  • LiteLLM runs inside a container; your model runs on the host.
  • Docker Desktop (macOS/Windows) provides host.docker.internal automatically.
  • Linux and WSL2 do not — this line creates it.
  • Harmless on macOS, required on Linux. One uniform file beats three variants.
Missing it is the single most common LiteLLM failure in this workshop: routes list fine, every completion fails.
© MHP Management- und IT-Beratung GmbH

LiteLLM · a production route, annotated

# PASSTHROUGH ROUTE BY DESIGN —
# no sampling params here at all
- model_name: qwen3.8-9b
  litellm_params:
    model: openai/qwen3.8-9b
    api_base: http://host.docker.internal:8090/v1
    api_key: dummy
    timeout: 1400
  • Passthrough sampling. The model's own tested recipe is authoritative; the gateway does not second-guess it.
  • timeout: 1400 — above llama-swap's health-check timeout, so a cold load is not mistaken for a crash.
  • Capitalised id — matches --served-model-name exactly.
The lesson: set sampling in the gateway only when you are deliberately overriding the model's recipe. Otherwise let it through.
© MHP Management- und IT-Beratung GmbH

Layer 5 · the point of all this

Qwen Code

Terminal agent: reads your repo, edits files, runs commands. Has qwen serve — a daemon with a browser UI.

OpenCode

Similar agent, provider-agnostic by design. Ships a model catalogue, so hosted providers need no config at all.

Both are configured with a base URL and a model name. Point them at http://127.0.0.1:4000 and they use whatever LiteLLM routes to.

Configuring both takes ten minutes — and teaches the real lesson: the stack is the durable investment. The client is interchangeable.

Concepts · models do not see words

They see tokens — chunks of text. Everything is measured in them: context size, price, speed.

1 token ≈ 4 characters ≈ 0.75 English words

# 19 characters ≈ 5 tokens
echo -n "The quick brown fox" | wc -c

A 500-word document is ~650 tokens. A large source file can be 3 000. This is why context runs out faster than you expect.

© MHP Management- und IT-Beratung GmbH

Concepts · the context window

The maximum tokens the model can attend to at once — your prompt + its reply + the whole conversation so far.

Exceed it and the start silently falls off the front. No error. The agent just forgets what you said twenty messages ago.

Context is not free

The engine allocates a KV cache that grows linearly with -c. A 1.3 GB model file at 128k context can have a KV cache larger than the model.

Default small. Start at -c 4096 and raise it only when you hit the wall.

© MHP Management- und IT-Beratung GmbH

Concepts · two context traps, measured

1 · -c 0 means "the model's own context", not zero

That is the default. On a 128k model it allocates a 128k KV cache and takes your laptop with it.

2 · parallel slots eat your context

Flagsn_ctx_seqWhat happened
-c 4096 (auto)4096auto enables a unified KV cache; slots share one pool
-c 4096 -np 14096one slot, full context
-c 4096 -np 41024explicit parallel divides it: 4096 ÷ 4
Typing -np 4 yourself gives each request a quarter of the context you asked for. Want four slots at 4096 each? Ask for -c 16384 -np 4.

For this workshop: use -np 1. You are one person.
© MHP Management- und IT-Beratung GmbH

Concepts · sampling, and the empty reply

Sampling

  • temperature 0.0–0.3 for code and tools; 0.8–1.2 for prose
  • Many models have a recommended recipe — read the model card

Thinking models

  • Can burn 4 000 tokens of reasoning to write 200 words of answer
  • If max_tokens is too small, the whole budget goes to thought and content comes back empty
An empty reply looks exactly like a crash and is not. Check reasoning_content — if it is huge and content is empty, raise max_tokens or pass --reasoning-budget 0.
© MHP Management- und IT-Beratung GmbH

Concepts · tool calling is what makes an agent

model ──> {"tool":"read_file","args":{"path":"main.py"}} your code runs it model <── {"result":"def main(): ..."} model ──> next step

The model emits structured JSON; your code runs it and feeds the result back. That loop turns a chatbot into an agent.

It is also the first thing that breaks on small models. A 1.7B fumbles the JSON; a 4B is marginal; expect 7B+ for dependable agents. llama.cpp needs --jinja so the model's own tool template is used.

Concepts · RAG: look it up, don't hope

documents ─> chunk ─> embedding model ─> vectors ─> store query ─> embedding model ─> vector ─> nearest neighbours ─> top-k chunks top-k chunks + query ─> chat model ─> answer (with citations)

Every piece runs locally on your laptop, and the embedding models are tiny — nomic-embed-text-v1.5 is 0.15 GB.
A small model plus good retrieval beats a big model guessing.

© MHP Management- und IT-Beratung GmbH

What small local models are actually good for

Genuinely good

  • Embeddings and retrieval — tiny models, excellent results, zero cost
  • Classification and extraction
  • Summarisation of short documents
  • Anything private — it never leaves the machine
  • Learning — you cannot understand these systems without running one

Genuinely bad

  • Correct code across many files
  • Reliable tool calling
  • Long reasoning chains
  • Anything needing current facts
For the right-hand column, the stack you build today routes to a cloud model. That is a feature, not a cop-out.

An agent is a loop. A pipeline is a loop with gates.

Agent harness — one task

  • One prompt in, one session, one model
  • qwen --model local-chat "…", OpenCode, an ADK agent
  • It stops when it thinks it is done

Dev pipeline — one job

  • spec → plan → exec → verify → review, each its own session
  • A different model per phase, chosen for that phase
  • It stops when the gates say so — tests, review, diff checks
A pipeline is not a smarter model. It is the discipline you add because the model is not smart enough: every phase's output is checked by something that cannot be talked out of it by confident prose.
© MHP Management- und IT-Beratung GmbH

Five things to remember

  1. Five layers. Build bottom-up, verify each one.
  2. The OpenAI-compatible API is why any client works with any server.
  3. Context costs RAM, and -np divides it. Quantisation costs quality.
  4. Tool calling breaks first as models shrink — and agents are built from tool calls.
  5. Self-hosting is a trade. RAG and private work win; frontier reasoning does not.
